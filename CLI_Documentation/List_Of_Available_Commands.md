# Available commands
There're about 12 commands available.

- check
- genauinfo
- gensubkey
- pkcsealedboxencryptdata
- pkcsealedboxdecryptdata
- pkcsigndata
- pkcverifydata
- skcinitialize
- skcencryptdata
- skcdecryptdata
- arweaveuploaddata
- version

All of these commands are **sudo** in nature except **genauinfo** command.

## Check command (Local)
There're no available options for this command.

**This needs to be called once so that necessary directories or folders can be created in advance..**

**'ServerIP' directory/folder must have 'IP.txt' with the API IP Address of SHSM Server**

## GenAUInfo (Local)
There're 3 options for this command.

```
--algorithm <algorithm>
--public_contact <public_contact>
--duration <duration>
```

- algorithm: It accepts only ED25519 or ED448 as digital signature algorithms
- public_contact: What will be the publicly disclosable contact like your public email or something similar that will be anchor to Arweave
- duration: How long will this authorized user information be valid in months (minimum is 1 and maximum is 6)?

**This command primarily helps developers or users to create the necessary AUInfo JSON data String to be anchored to Arweave in advance**

**Make sure that all necessary information was copied and paste in your own client device.**

**Kindly make sure that the directory which had the name of user_id on the server side or hosting/deploy machine don't have the private and sensitive data on them**

**Assume the folder/directory was called 'k3QHNHeFaGAWfdu8sKPcvIbLOR0dINvr', inside that folder on the hosting/deploy machine must be empty.
You can leave the directory/folder name as default which was generated by using user_id.
Changing the directory/folder name might cause runtime error in some cases..**

**Kindly perform the safe/secure operation as required after doing ```gensubkey``` command.**

## GenSubKey (Local)
There're 3 options for this command.

```
--algorithm <algorithm>
--user_ID <user_ID>
--duration <duration>
```

- algorithm: It accepts only ED25519 or ED448 as digital signature algorithms
- user_ID: What will be the user_ID/directory name?
- duration: How long will this authorized user information be valid in months (minimum is 1 and maximum is 5)?

**This command also helps developers or users to create the necessary JSON data String but requires information generated previously by ```genauinfo```**

**The two JSON data Strings from ```genauinfo,gensubkey``` must have one respective ```Arweave``` ID. Without the Arweave IDs, SHSM CLI, client and server won't work.**

**The information generated by this command are ```sudo``` by default. Hence you don't need to do same safe/secure operation like in ```genauinfo```**

## PKCSealedBoxEncryptData (Local)
**SealedBoxPublicKey.txt** must exist within **PublicKeyCryptography** folder.

There're 3 options for this command.

```
--algorithm <algorithm>
--data <data>
--encoding <encoding>
```

- algorithm: It accepts only XSalsa20Poly1305 and XChaCha20Poly1305 symmetric encryption algorithms. (0=XSalsa20Poly1305, 1=XChaCha20Poly1305)
- data: The String data to be encrypted
- encoding: What's the encoding used? (0=UTF8/Unicode,1=Base64)

**There is unsolvable side-channel attacks on 'data' and there seemed to be no ways to solve it especially if the data is really sensitive/private to begin with.**

**In such a regard, kindly make sure the hosting/deploy machine is trusted/secure to begin with.**

## PKCSealedBoxDecryptData
There're 5 options for this command.

```
--algorithm <algorithm>
--data <data>
--encoding <encoding>
--encoding_output <encoding_output>
--user_ID <user_ID>
```

- algorithm: It accepts only XSalsa20Poly1305 and XChaCha20Poly1305 symmetric encryption algorithms. (0=XSalsa20Poly1305, 1=XChaCha20Poly1305)
- data: The String data to be encrypted
- encoding: What's the encoding used? (0=UTF8/Unicode,1=Base64)
- encoding_output: What encoding do you want to use to output the String data? (0=UTF8/Unicode,1=Base64)
- user_ID: What will be the user_ID/directory name?

**There is unsolvable side-channel attacks on 'data and outputted_data' and there seemed to be no ways to solve it especially if the data is really sensitive/private to begin with.**

**In such a regard, kindly make sure the hosting/deploy machine is trusted/secure to begin with.**


## SKCEncryptData
Description:
- Encrypt data with a pair of imported secret keys

Usage:
- SHSM_CLI skcencryptdata [options]

Options:
```
  --aes_algorithm <aes_algorithm>                    The AES algorithm to be used to encrypt data
                                                     -1=No option choosen, 0=AES256GCM(Hardware Accelerated/Secure AES),
                                                     1=AEGIS256(HA/SA), 2=AEGIS128L(HA/SA) [default: -1]
  --aead_algorithm <aead_algorithm>                  The AEAD algorithm to be used to encrypt data
                                                     -1=No option choosen, 0=XChaCha20Poly1305IETF,
                                                     1=ChaCha20Poly1305IETF, 2=ChaCha20Poly1305
                                                      [default: -1]
  --streamcipher_algorithm <streamcipher_algorithm>  The AEAD algorithm to be used to encrypt data
                                                     -1=No option choosen, 0=XChaCha20,
                                                     1=XSalsa20, 2=ChaCha20
                                                     3=ChaCha20IETF, 4=Salsa20
                                                     5=Salsa12, 6=Salsa8 [default: -1]
  --mac_algorithm <mac_algorithm>                    The MAC algorithm
                                                     -1=No option choosen, 0=HMACSHA512256
                                                     1=HMACSHA512, 2=HMACSHA256
                                                     3=Poly1305 [default: -1]
  --data <data>                                      Input String data to be encrypted
  --additional_data <additional_data>                Input String 'additional data' to be submitted
  --encoding <encoding>                              The type of encoding for both inputted Strings.
                                                     (0=UTF8/Unicode,1=Base64) [default: 0]
  --user_ID <user_ID>                                What will be the user ID?
```

**If you want to use AES algorithms, kindly make sure the hosting/deploying device supports secure variant of AES algorithm.**

**Under most circumstance, one can use AEAD algorithms or stream cipher algorithms paired with MAC algorithms.**

**Additional Data only applies to AES and AEAD algorithms.**

**Using AES or AEAD algorithms won't need to specify MAC algorithm**

**MAC algorithm must be paired with stream cipher algorithm**

## SKCDecryptData
Description:
- Decrypt data with a pair of imported secret keys

Usage:
- SHSM_CLI skcdecryptdata [options]

Options:
```
  --aes_algorithm <aes_algorithm>                    The AES algorithm to be used to encrypt data
                                                     -1=No option choosen, 0=AES256GCM(Hardware Accelerated/Secure AES),
                                                     1=AEGIS256(HA/SA), 2=AEGIS128L(HA/SA) [default: -1]
  --aead_algorithm <aead_algorithm>                  The AEAD algorithm to be used to encrypt data
                                                     -1=No option choosen, 0=XChaCha20Poly1305IETF,
                                                     1=ChaCha20Poly1305IETF, 2=ChaCha20Poly1305
                                                      [default: -1]
  --streamcipher_algorithm <streamcipher_algorithm>  The AEAD algorithm to be used to encrypt data
                                                     -1=No option choosen, 0=XChaCha20,
                                                     1=XSalsa20, 2=ChaCha20
                                                     3=ChaCha20IETF, 4=Salsa20
                                                     5=Salsa12, 6=Salsa8 [default: -1]
  --mac_algorithm <mac_algorithm>                    The MAC algorithm
                                                     -1=No option choosen, 0=HMACSHA512256
                                                     1=HMACSHA512, 2=HMACSHA256
                                                     3=Poly1305 [default: -1]
  --data <data>                                      Input String data to be decrypted
  --additional_data <additional_data>                Input String 'additional data' to be encrypted
  --encoding <encoding>                              The type of encoding for both inputted Strings. (0=UTF8/Unicode,1=Base64) [default: 0]
  --output_encoding <output_encoding>                The type of encoding for decrypted data. (0=UTF8/Unicode,1=Base64) [default: 0]
  --user_ID <user_ID>                                What will be the user ID?
```
Similar situation like encrypting with a pair of imported secret keys..

## ArweaveUploadData
Description:
- Upload data to arweave in a memory safe manner..

Usage:
- SHSM_CLI arweaveuploaddata [options]

Options:
```  
  --data <data>        Input normal string data or JSON string data
  --user_ID <user_ID>  What will be the user ID?
```

**This needs to pre-import Arweave RSA key to SHSM Server side in advance using SHSM Client**
